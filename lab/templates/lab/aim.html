To perform and observe the four fundamental persistent-storage operations on a relational database table, and to relate each operation to the SQL statement, the HTTP method and the Django ORM call that carries it out.

Learning Objectives

After completing this virtual lab experiment, students will be able to:

  1. Identify the four CRUD operations: describe Create, Read, Update and Delete, and name the SQL statement that carries out each one.

  2. Explain the role of a primary key: show how id identifies a row, why the database rather than the client assigns it, and why a deleted identifier is never reissued.

  3. Demonstrate a constraint violation: cause a UNIQUE constraint to refuse a write, and distinguish that refusal from a validation error raised by the application.

  4. Trace a request through Django: follow one operation through urls.py → views.py → forms.py → models.py → template, and identify which file actually changes.

  5. Compare the three interfaces: perform the same operation through an HTML form, by typing SQL, and as a Django ORM expression, and relate the three to one another.

The four operations

CREATE

INSERT INTO students

Add a new row. The database assigns the primary key — you never supply it.

READ

SELECT FROM students

Retrieve rows, with or without a condition. Changes nothing.

UPDATE

UPDATE students SET …

Rewrite columns of an existing row, located by its id. The id is preserved.

DELETE

DELETE FROM students

Remove a row permanently. Its identifier is retired and never reissued.
