Database Systems · Experiment 1

Performing CRUD Operations on a Relational Database

Create, Read, Update and Delete — the four operations every data-driven application is built from. Perform each one on a live table and see the SQL statement and the Django ORM call behind it.

Aim

To perform and observe the four fundamental persistent-storage operations on a relational database table, and to relate each operation to the SQL statement, the HTTP method and the Django ORM call that carries it out.

Learning outcomes

After completing this experiment, you will be able to:

  • Describe the four CRUD operations and name the SQL statement for each.
  • Explain how a primary key identifies a row, and why identifiers are never reused.
  • Demonstrate how a UNIQUE constraint causes the database to refuse a write.
  • Trace one operation through Django's URL → view → form → model → template path.
  • Distinguish validation performed by the application from constraints enforced by the database.
  • Carry out the same operation three ways: through a form, by typing SQL, and in the ORM.

The four operations

CREATE

INSERT INTO students

Add a new row. The database assigns the primary key — you never supply it.

READ

SELECT FROM students

Retrieve rows, with or without a condition. Changes nothing.

UPDATE

UPDATE students SET …

Rewrite columns of an existing row, located by its id. The id is preserved.

DELETE

DELETE FROM students

Remove a row permanently. Its identifier is retired and never reissued.
